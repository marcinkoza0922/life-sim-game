# Life Sim (working title) — on the Hearth engine

A lightly comedic 3D life simulator / virtual dollhouse written in Rust on a custom archetype ECS.
See [`docs/DESIGN.md`](docs/DESIGN.md) for the full design.

## Run

```sh
cargo run --release -p game --bin lifesim            # play (starter family, seed 7)
cargo run --release -p game --bin lifesim -- --seed 3 --minutes 300   # different family, 5h in
cargo run --release -p game --bin lifesim -- --creator                 # start in Create-a-Household
cargo run --release -p game --bin lifesim -- --load saves/quicksave.ron
```

### Controls

| Input | Action |
|---|---|
| LMB on a household member | select |
| LMB on object / other peon / floor | action menu for the selected peon (Shift+LMB on household member to interact) |
| RMB drag / Q E | rotate camera |
| MMB drag / WASD / arrows | pan |
| Wheel / `+` `-` | zoom |
| PgUp / PgDn | change level (basements are negative) |
| Space, 1–4 | pause, speed (1x / 2x / 3x / Ultra) |
| F5 / F6 / F7 | Live / Buy / Build mode (time pauses while building) |
| R | rotate object / stairs being placed |
| V | wall mode: cutaway → down → up (roofs show over the viewed level only with walls up) |
| T / M | toggle roofs / mute gibberish voices |
| Ctrl+S / Ctrl+O | quicksave / quickload (`saves/quicksave.ron`); ☰ Game menu also has New household and Neighborhood |
| Tab / Home | next peon / focus camera on selected peon |
| Delete | sell hovered object (Buy mode) |
| L | story log |
| F12 | screenshot to `screenshots/` |
| Esc | close menu / cancel tool / back to Live |

### Debug tools (in game)

| Key | Window |
|---|---|
| F1 | ECS inspector: every entity and a Debug dump of each component |
| F2 | Autonomy: the selected peon's scored options ("why did they do that?"), boredom list |
| F3 | Overlays: room ids, object occupancy, walk paths; tile/room info under the cursor |
| F4 | Profiler: frame time, per-system sim timings, draw/batch counts |
| F8 | Lighting, sim settings & cheats: free will, lifespan scale, aging/bills/accidents, +money, max needs, age up, hot-reload `assets/data` |

## Headless tooling (`simctl`)

```sh
cargo run --release -p simctl -- run --days 3 --seed 1          # daily JSON summaries, time budget per peon, story log
cargo run --release -p simctl -- run --days 3 --seed 1 --trace Priya   # every action start/finish with needs
cargo run --release -p simctl -- check --seeds 40 --days 6      # invariant sweep (starvation, collapse, idling, bankruptcy)
cargo run --release -p simctl -- render --hour 21 --level 1 --out out/night.png   # offscreen PNG of the lot
cargo run --release -p simctl -- render --hour 19 --order tv_basic:watch --target 11,16 --dist 9 --yaw 200 --out out/tv.png  # stage everyone doing X
cargo run --release -p simctl -- lineup --pose walk --time 0.3 --out out/lineup.png  # every life stage's rigged body
cargo run --release -p simctl -- lineup --anim read --prop book --time 1 --out out/read.png  # an interaction clip + prop
```

### Character models

Peon bodies are rigged glTF files in `assets/models/`, generated by a Blender script and embedded in
the binaries. After editing the script, regenerate them (Blender 4.4+, headless):

```sh
blender -b --factory-startup -P assets/blender/make_peons.py            # all stages
blender -b --factory-startup -P assets/blender/make_peons.py -- adult   # just one
```

`lifesim` also has test hooks for automated captures of the full UI:
`--screenshot-after FRAMES PATH --mode live|buy|build --level L --debug --cam YAW,PITCH,DIST --menu-on OBJECT_ID`.

## Layout

| Crate | What |
|---|---|
| `crates/hearth_ecs` | custom archetype ECS (entities, queries with runtime borrow checks, resources, events, deferred commands, schedule) |
| `crates/hearth_render` | wgpu 30 renderer: instanced PBR-lite, GPU-skinned glTF models, sun shadows, point lights, MSAA, offscreen capture |
| `crates/sim` | the simulation — deterministic, headless; needs, autonomy, actions, nav, lot/rooms, careers, aging, death, economy |
| `crates/game` | the `lifesim` binary plus scene building, camera, tools and egui UI |
| `crates/simctl` | headless runner, invariant checker, offscreen renderer |
| `assets/data` | RON content: objects, traits, quirks, socials, moodlets, careers, names |
| `assets/models`, `assets/blender` | rigged peon bodies per life stage and the Blender script that generates them |

### Lighting quality

Open **☰ Game → Lighting settings** or **F8** to toggle ambient occlusion, indirect
light, sun shadows, and soft shadow filtering. Preferences persist in `graphics.ron`
separately from audio and saved households. AO and soft sun shadows are enabled by
default; indirect light is opt-in because it costs more GPU time.

AO traces four short world-space hemisphere rays against up to 128 nearby oriented
mesh bounds, adding contact shading beyond material texture AO. Indirect light uses
eight rays and adds approximate one-bounce diffuse color from nearby surfaces,
including sunlight visibility and emissive surfaces. These are box proxies rather
than triangle-accurate GI: hollow/complex meshes can over-occlude, animated characters
receive indirect light but do not contribute occlusion, and distant geometry outside
the proxy budget is omitted. The detailed region follows the camera focus.
Disabling both effects skips proxy collection and tracing. Disabling sun shadows
skips the shadow pass; disabling soft filtering reduces each shadow lookup from
nine comparisons to one. Direct lighting, material AO, fog, and ACES remain active.

Offscreen comparisons: `cargo run -p simctl -- render --no-ao --out out/baseline.png`
and `cargo run -p simctl -- render --indirect-light --out out/indirect.png`.
The renderer tool also accepts `--no-shadows` and `--hard-shadows`.
