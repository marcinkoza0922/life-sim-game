# CLAUDE.md

## Build and test

Keep output small: quiet flags first, full output only for what failed.

- Tests: `cargo nextest run` (quiet profile in `.config/nextest.toml`: only failures print).
  Narrow with `-p <crate>` or a test-name filter.
- Never use `cargo test`, except `cargo test --doc` for doctests (nextest doesn't run them).
- Lint: `cargo clippy --all-targets --message-format=short -q -- -D warnings`
- Build check: `cargo check --message-format=short -q`
- On failure only, re-run just the failing test or crate with full output
  (e.g. `cargo nextest run -p sim <test_name> --no-capture`). Don't dump full build logs.
- When piping cargo output through `tail`/`grep`, run `set -o pipefail` first so the exit code survives.
- Backtraces are off (`RUST_BACKTRACE=0` in `.claude/settings.json`). To debug a panic, enable
  them for that one command: `RUST_BACKTRACE=1 cargo nextest run <test_name>`.
- Never run `cargo clean` unless asked.
- Don't read `target/`. `out/` and `screenshots/` hold generated renders/logs: open specific files only.

## Asset tools (MCP)

Current pipeline: object art is a static glTF per object, `assets/models/objects/<id>.glb`, generated
by `assets/blender/make_objects.py` (game-space helpers, conventions in its docstring); objects without
one fall back to the greybox primitives in `assets/data/objects.ron` (`color`/`rough`/`metal` per part),
which also stay the picking shapes; peons are generated by `assets/blender/make_peons.py` into
`assets/models/*.glb` (embedded via `include_bytes!`); voices are synthesized in `game/src/audio.rs`;
UI is our own `hearth_ui` crate (egui only for F1–F8 developer windows), with fonts bundled from
`assets/fonts/`. Material textures (`assets/textures/<id>/`, see its README) are box-projected, so they
need no UVs. UI icon art lives in `assets/ui/icons/` (see VectorCraft below); sound effects are `assets/audio/sfx/*.ogg`
(see SoundCraft below).

- **Blender** (`blender` MCP, or `blender -b -P <script>`): meshes, rigs, animation clips. Prefer
  extending a checked-in generator script over hand-editing a .blend, so models stay reproducible.
  This is the right tool for "real art" for an object (glTF replacing greybox parts).
- **MaterialCraft** (procedural PBR materials) and **TextureCraft** (painting/baking on a mesh):
  `hearth_render` samples tiling materials triplanar-style (albedo, OpenGL normal, ORM texture arrays):
  list the id in `assets/data/materials.ron`, export maps to `assets/textures/<id>/`, and reference it
  with `material:` on a RON part (floor/wall styles map to ids in `game/src/scene.rs`).
  MaterialCraft is for these tiling surfaces (floors, walls, wood, fabric): add a function to
  `assets/materialcraft/materials.py` (builds the .sbs and maps via `materialcraft-cli batch`; its
  library has only atomic nodes, so patterns are pixel-processor expressions) and preview with
  `simctl materials`. Gotchas: graph colours are linear (base colour is sRGB-encoded on export); the
  pixel-processor evaluator doesn't share sub-expressions, so heavy shared noise exceeds its execution
  budget and cooks magenta (the script cooks first and fails on errors). Meshes have no UVs yet, so
  TextureCraft's unique per-model maps need a UV vertex attribute and a UV sampling path first (say so
  rather than producing maps nothing loads).
- **PhotoCraft**: raster images: reviewing or annotating `simctl render` / `screenshots/` output,
  contact sheets, reference boards, any future PNG asset (icons, thumbnails, splash).
- **VectorCraft**: icon/UI art (bubble icons, catalog/category icons, logo). Icons are hand-written
  SVG in `assets/vectorcraft/make_icons.py` (64×64 viewBox, theme colours, 3.5 plum outline, white
  gloss); running it writes `assets/vectorcraft/icons/*.svg` + `sheet.svg` (contact sheet) and
  rasterises 128 px PNGs into `assets/ui/icons/` via `vectorcraft-cli run --in X.svg --export X.png
  --scale 2` (headless, no MCP needed). To add one: add it to `ICONS`, rerun, add the variant to the
  `icons!` list in `game/src/icons.rs`, which embeds them and registers each at its drawn pixel size
  (`IconSize`) because the UI image atlas has no mipmaps. Build tools, Buy categories and Sell use
  them; the remaining HUD/menu icons are still Noto Emoji.
- **Sounds: CC0 first.** Prefer downloaded CC0 recordings: `assets/audio/fetch_sfx.py` pins each source
  (OpenGameArt URL or a file in Kenney's All-in-1 bundle at `~/Kenney Game Assets All-in-1 3.8.0`,
  `KENNEY_DIR` to override; it also has Music Loops/Jingles) by SHA-256, trims one-shots, cuts seamless
  loops (steadiest stretch, or re-laid hits for rhythmic sources), encodes `assets/audio/sfx/<id>.ogg`
  and rewrites `assets/audio/CREDITS.md`. Add the id to the `sfx!` list in `game/src/sounds.rs`.
- **SoundCraft**: only for sounds with no good CC0 recording (TV, stir, scrub, treadmill, snore), built
  headless by `assets/soundcraft/make_sfx.py` (built-in synth/drum notes and generated noise per session;
  `soundcraft-cli script` bounces, sox normalises, ffmpeg encodes Ogg). Gotchas: plugin params use
  real units (ms, %, semitones; `soundcraft-cli plugins`) and choice params take indices; MIDI is 960 PPQ
  at 120 bpm; use the 7-band EQ's 24 dB/oct filters, the 1-band EQ is too gentle on noise. Speech stays
  synthesized.

The craft MCP servers are user-scoped, and their read/write root is `~/CreativeWork` (outside the repo).
Do scratch work there, e.g. `~/CreativeWork/life-sim-game/<tool>/`, and copy results into the repo; the tools
can't write into it directly. Shipped outputs go
under `assets/` next to the code that loads them (e.g. `assets/textures/`, `assets/ui/`, `assets/audio/`),
and sources worth keeping (`.sbs`, `.tcraft`, `.pcraft`, vector docs, sessions) go in
`assets/<tool>/` like `assets/blender/`. When a feature adds a new kind of asset, also add the loading
code and update the `assets/` tree in `docs/DESIGN.md`.
